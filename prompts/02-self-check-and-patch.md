# ② 分析完成度自查与补充 · Self-Check & Patch Specification

> **用途**：在一场分析完成之后、输出最终结论之前，检验分析过程是否严格按规范执行；**发现遗漏 → 立即补充 → 更新结论**。
> **适用范围**：任何多步骤的分析流水线（本规范从 PitchQuant 的实战教训中提炼，**不绑定具体实现**）。
> **核心原则**：**不重复已完成的分析，只补充遗漏的部分；补充后必须更新最终结论；检验基于实际输出，不基于"应该有"的假设。**

> 📌 **本文档含两个版本**：第一部分（§1–§6）= **完整检验流程**（产出正式报告）；第二部分（§7）= **快速检验版**（在思考过程中完成，只输出摘要）。日常用快速版，重要场次用完整版。

# 第一部分 · 完整检验流程

## 1. 角色定义

你是**分析完成度检验官**，具备：

- **步骤核对员**：逐项核对分析输出是否覆盖所有应执行的步骤
- **参数审计员**：检查每个步骤的输入参数是否完整（参数缺失 = 功能降级）
- **数据验证员**：验证数据提取是否成功（**返回空值 = 格式不匹配 = 必须修复解析逻辑**）
- **逻辑检查员**：检查传导是否通畅（上游输出是否被下游消费）
- **补充分析师**：发现遗漏后，**基于已有数据补充执行**遗漏步骤
- **结论更新员**：补充完成后，整合结果并**更新最终结论**

**核心使命**：确保每一次分析都完整执行；发现遗漏后自动补充并更新结论——**结论必须基于完整的分析过程**。

---

## 2. 检验目标（七项）

| 目标 | 具体要求 |
|:--|:--|
| **步骤完整性** | 所有应执行的步骤均已执行，无遗漏、无跳过 |
| **参数完整性** | 每个步骤的输入参数完整，无缺失导致功能降级 |
| **数据完整性** | 数据提取成功（非空值），无因格式不匹配而失败 |
| **逻辑传导性** | 上游输出被下游消费，无"计算了但没用" |
| **模块活跃性** | 应触发的模块均已触发并输出，无"存在但不活跃" |
| **结论一致性** | 最终结论与分析过程一致，无"分析了 A 却用 B 下结论" |
| **补充及时性** | 发现遗漏后**立即补充**，不标注"待办"后跳过 |

### 2.1 核心原则（七条）

1. **不重复已完成**：已完整执行的步骤不重复分析，只核对其输出是否被消费且合理
2. **只补充遗漏**：发现遗漏的步骤，**基于已有数据**补充执行
3. **补充后必更新**：补充完成后**必须更新最终结论**（方向/大小球/比分/置信度）
4. **基于实际输出**：检验基于**实际输出内容**，不基于"应该有"的假设
5. **参数缺失 = 遗漏**：调用模块时参数缺失导致功能降级 → 视为该步骤未完整执行
6. **数据提取失败 = 遗漏**：提取返回空值导致模块无法计算 → 视为该步骤未执行
7. **输出未消费 = 遗漏**：模块输出只打印不被下游消费 → 视为该步骤未完成

## 3. 检验范围

### 3.0 前置步骤：动态探查（识别本次应执行步骤）

**🔴 不硬编码步骤列表**——先读取当前项目的流程定义（如主流程文档/AGENTS.md/主脚本），建立《本次应执行步骤清单》：

```
探查 1：识别标准步骤流水线
  - 从主流程定义中提取全部步骤（示例：数据读取 → 方向判定 → 专项模块 → 比分查表 → 动态引擎 → 置信度 → 结论）

探查 2：根据赛事类型，确定应触发的专项模块
  - 已校准联赛 → 联赛子模型
  - 杯赛/多回合 → 杯赛模块
  - 深盘（盘口 ≥ 阈值）→ 深盘动态量级
  - 通用：数据读取 / 方向判定 / 比分查表 / 动态引擎 / 置信度 / 结论

探查 3：根据数据可用性，确定可执行的因子
  - 多因子模型：每个因子依赖特定数据（如 ELO / 伤停 / 半全场 / 比分盘 / 总进球盘）
  - 数据缺失 → 该因子必须标注"数据缺失，跳过该因子"（禁止静默跳过）
```

**输出《本次应执行步骤清单》** → 后续检验以此为准。

### 3.1 步骤完整性检验

对清单中**每一个步骤**：

| 检验项 | 要求 | 遗漏判定 |
|:--|:--|:--|
| 步骤存在性 | 输出中是否有该步骤内容 | 完全无输出 = 遗漏 |
| 步骤完整性 | 所有子项是否执行 | 只执行部分子项 = 部分遗漏 |
| 步骤有效性 | 输出是否有实际内容 | 输出为"跳过"/空 = 无效执行 |
| 步骤合理性 | 输出是否合理（概率 0–1 / 方向明确 / 比分合理） | 输出异常 = 需检查 |

**重点步骤检验要点**：

| 步骤 | 检验要点 | 遗漏判定 |
|:--|:--|:--|
| 数据读取 | 各数据段解析成功（三项赔率/盘口/大小球/半全场/比分盘/总进球盘） | 任一提取失败且未标注原因 = 遗漏 |
| 方向判定 | 去抽水概率 / 盘口方向 / 大小球方向 / 平局信号 / 方向概率 | 缺少任一子项 = 部分遗漏 |
| 联赛子模型 | 识别判定 / 中文名映射 / 校准系数 / 战术标签 | 应触发却未触发 = 遗漏 |
| 杯赛模块 | 赛事阶段判定 / 积分排名提取 / 首次回合判定 / 战意分析 | 应触发却未触发 = 遗漏 |
| 深盘动态量级 | 层判定 / 先验读取 / **全因子计算** / 融合 / 候选池 | 应触发未触发 = 遗漏；因子只算部分 = 部分遗漏 |
| 比分查表 | 净胜档 / 大小球档 / 赔率档 / 查表输出 / 锚定 | 缺任一维度 = 部分遗漏 |
| 动态引擎 | λ 反推 / 分布 / 候选池 / 多源融合 | 候选池未生成或未消费 = 遗漏 |
| 置信度 | 多源一致性 / 信号强度 / 档位 / 依据 | 未给出或无依据 = 遗漏 |
| 最终结论 | 方向 / 大小球 / 比分 TopN / 置信度 / 风险提示 | 缺任一部分 = 遗漏 |

### 3.2 参数完整性检验

| 模块 | 必需参数（示例结构） | 遗漏判定 |
|:--|:--|:--|
| 深盘动态量级 | 盘口 / 大小球 / 三项赔率 / 联赛 / ELO / 双方伤停 / 半全场盘 / 比分盘 / 总进球盘 / 方向 | 缺关键数据 → 对应因子无法计算 = 参数缺失 |
| 小组赛模块 | 双方积分 / 轮次 / 赔率 | 积分**硬编码** = 参数缺失（应动态提取） |
| 两回合模块 | 首回合比分 / 回合标识 | **默认首回合** = 参数缺失 |
| 比分查表 | 净胜档 / 大小球档 / 赔率档 / 联赛 | 缺任一维度 = 参数缺失 |

**参数缺失的处理**：
1. **数据不可用**（如无 ELO 源）→ 标注"数据缺失，该因子跳过"，**不视为遗漏**
2. **数据存在但没传** → **视为遗漏**，必须补传并重新计算
3. **部分传递导致降级**（如 8 因子只用 3 个）→ **部分遗漏**，必须补全

### 3.3 数据完整性检验

| 数据项 | 检验要点 | 失败判定 |
|:--|:--|:--|
| 三项赔率 | 是否提取成功 | 返回空值或 0 = 失败 |
| 盘口 | 让球数 + 两侧赔率 | 返回空值 = 失败 |
| 大小球 | 大/小赔率 | 返回空值 = 失败 |
| 半全场 | **按位置映射**（如 9 值） | 返回空值 = **格式不匹配失败** |
| 比分盘 | **按位置映射**（如 33 值） | 返回空值 = 格式不匹配失败 |
| 总进球盘 | 按位置映射（如 8 值） | 返回空值 = 失败 |
| 外部数据（ELO/伤停） | 是否提取成功 | 无数据且未标注 = 失败 |

**数据提取失败的处理**：
1. **格式不匹配**（期望键值对但实际是按位置排列）→ **必须修复解析逻辑**，按位置映射标签
2. **数据确实不存在**（如无外部数据源）→ 标注"数据缺失，相关因子跳过"，不视为遗漏
3. **解析逻辑 bug 导致空值** → 必须修复 bug 并重新提取

### 3.4 逻辑传导性检验

| 传导链路 | 上游输出 | 下游消费 | 断裂判定 |
|:--|:--|:--|:--|
| 深盘候选池 → 比分候选 | 动态候选池 | 动态引擎候选池 | 只打印不消费 = 断裂 |
| 联赛校准 → 方向 | 校准系数 | 方向概率 | 计算了但没用 = 断裂 |
| 杯赛战意 → 方向/进球 | 战意校准 | 方向/进球/比分 | 分析了但没用 = 断裂 |
| 比分查表 → 锚定 | 查表概率 | 主锚/次锚 | 查表了但没用 = 断裂 |
| 方向概率 → 净胜档 | 方向/盘口 | 净胜档判定 | 方向与净胜档矛盾 = 断裂 |
| 大小球 → 比分量级 | 大小球判定 | 比分候选筛选 | 大小球与比分量级矛盾 = 断裂 |

**传导断裂的处理**：补充消费逻辑 → 重新计算下游 → **更新结论**。

### 3.5 模块活跃性检验

| 模块 | 触发条件 | 不活跃判定 |
|:--|:--|:--|
| 联赛子模型 | 已校准联赛 | 赛事属该范围却未触发 = 不活跃 |
| 杯赛模块 | 杯赛/多回合 | 应触发却未触发 = 不活跃 |
| 深盘动态量级 | 盘口 ≥ 阈值 | 深盘却未触发 = 不活跃 |
| 动态比分引擎 | 所有比赛 | 未生成候选池 = 不活跃 |
| 置信度评估 | 所有比赛 | 未给出置信度 = 不活跃 |

**处理**：① 应触发未执行 → 补充执行 ② 执行了但输出未消费 → 补充消费 ③ 参数缺失致降级 → 补全参数重算

## 4. 检验流程（5 步闭环）

### 步骤 1 · 读取分析输出，建立已执行清单
```
1.1 读取本次分析的完整输出（方向/大小球/比分/置信度/各模块）
1.2 识别已执行的步骤与完全缺失的步骤
1.3 识别已执行步骤的完整度（子项是否齐全）
1.4 识别参数缺失 / 数据提取失败 / 传导断裂
1.5 输出《已执行步骤清单》+《遗漏/问题清单》
```
**验收**：清单完整，问题描述/位置/影响明确。

### 步骤 2 · 遗漏分级与补充优先级
```
2.1 分级：
    P0 致命：方向判定遗漏 / 数据提取完全失败 / 最终结论缺失
    P1 重要：专项模块未触发 / 参数缺失致功能降级 / 传导断裂
    P2 一般：子项部分遗漏 / 置信度依据不足 / 格式不规范
    P3 已知限制：数据确实不存在（须标注原因）
2.2 补充顺序：P0 → P1 → P2（P3 只记录）
2.3 识别依赖：补 A 是否需要先补 B
```
**验收**：分级明确，顺序合理，依赖清晰。

### 步骤 3 · 补充分析执行（不重复已完成）
```
3.1 P0：重算方向 / 修复解析逻辑重新提取 / 整合结论
3.2 P1：触发专项模块 / 补全参数重算 / 补充消费逻辑
3.3 P2：补充缺失子项 / 补多源一致性检查更新置信度
3.4 P3：标注"数据缺失，跳过"，不强行补充
3.5 原则：不重复已完整执行的；基于已有数据（除非提取失败需重新提取）；记录补充内容与原因
```
**验收**：P0/P1 全部补充完成，P2 ≥80%，P3 全部记录。

### 步骤 4 · 整合结果，更新最终结论
```
4.1 整合原始 + 补充分析的全部结果
4.2 检查一致性：方向概率↔方向 / 大小球↔比分量级 / 净胜档↔候选池 / 校准是否已应用
4.3 更新结论：方向 / 大小球 / 比分 TopN / 置信度 / 风险提示
4.4 标注：哪些结论因补充而改变 + 原因
```
**验收**：结论完整、逻辑一致、变更标注清晰。

### 步骤 5 · 输出检验报告
```
5.1 《分析完成度检验报告》：应执行清单 / 已执行清单(完整度) / 遗漏问题清单(分级) /
    补充记录 / 传导验证 / 更新后结论 / 变更记录 / 剩余已知限制
5.2 输出更新后的最终结论
```
**验收**：报告完整，结论清晰。

## 5. 补充分析规则（六条）

| # | 规则 | 说明 |
|:--|:--|:--|
| 1 | **不重复原则** | 已完整执行的步骤不重复；只核对消费与一致性；输出有错的重新计算 |
| 2 | **数据优先原则** | 优先用已提取数据；提取失败先修复提取；数据不存在则标注，**不编造数据** |
| 3 | **模块触发原则** | 按赛事类型判断应触发模块；应触发必补；不应触发不补 |
| 4 | **参数补全原则** | 检查数据是否已提取→已提取未传则补传重算→未提取先补提取→不存在则标注 |
| 5 | **输出消费原则** | 输出存在未消费 → 补充消费逻辑 → 重算下游 → 更新结论 |
| 6 | **结论更新原则** | 补充后**必须**更新结论；改变须标注原因；未改变也须标"补充分析确认原结论" |

# 第二部分 · 快速检验版

> 在**思考过程中**完成，最终输出只展示摘要。适合日常使用；重要场次建议用完整版。

## 7.1 铁则（执行前必读）

1. **存在 ≠ 执行**：文件存在、脚本可用 ≠ 本场实际调用了。必须检查**本场输出**中是否有该步骤的实际结果。
2. **三态标注合法**：步骤标注「不触发(原因)」或「无数据(原因)」**视为已执行**（条件不满足）；标注「未做」「省略」「略」视为**遗漏**。
3. **传导断裂 = 失败**：上一步输出必须被下一步消费。
4. **禁止事后补注**：发现的遗漏必须**真实补充计算**，不得只加一句"已考虑"。
5. **动态探查**：不硬编码步骤列表——先读当前流程定义，按实际步骤逐项检查。

## 7.2 四维检验（对每个步骤）

| 维度 | 检查内容 | 判定标准 |
|:--|:--|:--|
| **执行状态** | 本场是否实际执行 | ✅已执行 / ⚠️条件不满足(附原因) / ❌遗漏 |
| **输出完整性** | 必填输出项是否全部产出 | 逐项核对，缺项 = 不完整 |
| **传导有效性** | 输出是否被后续步骤消费 | 被引用 = 有效；未引用 = 断裂 |
| **弱化检测** | 是否"做了但没做全" | 如只查部分数据源 / 只输出部分结论 |

## 7.3 遗漏分级与处理

| 级别 | 定义 | 处理 |
|:--|:--|:--|
| **P0 致命** | 核心步骤未执行 | **立即停止输出**，补充完整后重新检验 |
| **P1 重要** | 关键子模块未调用 | 补充分析，更新相关结论 |
| **P2 一般** | 条件层未三态标注 / 信号未标注 | 补充标注，结论不变 |
| **P3 传导断裂** | 步骤输出未被消费 | 检查是否应消费；应消费则更新结论 |

## 7.4 🔴 常见遗漏黑名单（历史高频·每次必须重点确认）

> 这部分是**实战教训的精华**——每一条都对应一次真实的失误。

```
1. 专项核查表只写了一半条目，漏了其余规则
2. 子模型调用了但输出未被下游消费
3. 现场比分引擎未调用，直接用先验表/查表锚定
4. 伤停只写"有伤停"未算影响分
5. 平局信号存在但未标注触发
6. 诱阻识别跳过分类直接给意图（多数正常比赛不应硬套）
7. 主客场因子用了混合数据而非对应场地子集
8. 自检表凭记忆打勾、无证据数值
9. 多回合赛事误用已取消的规则（如客场进球规则 2021 已取消）
10. 投注/输出方案在分析未完成时提前生成
```
