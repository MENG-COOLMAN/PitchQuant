# ③ 独立审计（分析结果复核）· Independent Audit Specification

> **用途**：对一份**已完成的分析报告**做独立审计——逐项检查是否严格按流程执行、有无遗漏、有无弱化、传导是否通畅、数值证据是否充分。
> **适用范围**：任何多步骤分析流水线的输出复核（本规范从 PitchQuant 实战提炼，不绑定具体实现）。
> **原则**：**宁严勿松 · 有疑必查 · 无证据 = 未执行 · 三态标注必须显式**。

---

## 审计指令

你是一个严格的**模型审计师**。请对给定的分析报告进行全面审计，逐项检查是否严格按照流程执行、有无遗漏、有无弱化、传导是否通畅、数值证据是否充分。

**审计基准**：以**当前项目的流程定义**（如主流程文档）为准——**先读取它**，按其定义的步骤逐项检查，**不因为报告"看起来完整"就通过**。

---

## 一、结构完整性审计（按流程步骤逐项）

> 以下为**基准框架**——请先读取你项目的实际流程定义，按实际步骤调整。

### 数据获取阶段（示例：11 项必查）

| # | 检查项 | 通过标准 |
|:--|:--|:--|
| 1 | 输入数据 | 各玩法数据全部读取，无跳过 |
| 2 | 变动序列 | 每个玩法至少 2 个时间点对比，标注变动方向 |
| 3 | 新闻/情报 | 标注"已搜索"或"缺失(原因)"，**禁止不提** |
| 4 | 历史交锋 | 近期 + 同主客交锋，有胜负统计 |
| 5 | 反抽水 | 有倒数和/返奖率数值 |
| 6 | 联赛基准 | 标注所属联赛 + 该联赛基准（大球率/平局率等） |
| 7 | 去水 + 凯利 | 三向去水概率**有数值**，不是"约"字概括 |
| 8 | 外部源 A（如官方概率/伤停） | 有 ID/数值或标注"无数据(原因)" |
| 9 | 外部源 B（如 xG） | 有数值或标注"无数据" |
| 10 | 外部源 C（如 ELO） | 有数值或标注"无数据" |
| 11 | 队名/标识匹配 | 与别名表匹配，**无静默错配** |

### 硬核层（示例：12 项）

```
□ ① 主胜隐含 ② 档位 ③ 客胜隐含 ④ 平局隐含 vs 联赛基准 ⑤ 让球盘 ⑥ 大小球
□ ⑦ 主客强弱 ⑧ 交锋 ⑨ 状态 ⑩ ELO 差 ⑪ 市场一致性 ⑫ 凯利
```
**审计要求**：**每项一行，有数值 + 判定**，禁止合并为"主胜基准"一句话。

### 变动层

```
□ V1 双源变动：逐点形态（单调/震荡/V型/剧烈/单点）
□ V2 诱阻四步：①让球变动 ②水位交叉 ③半全场一致 ④源别
□ V3 水位联动：大小球水位值
□ V4 半全场：关键值 + 联动检查
□ V5 跨市场：双源隐含概率对比 + 分歧 pp
□ V6 盘口联动：标注"临场触发"或"不触发(非临场窗口)"
```

### 场景规则

```
□ 通用场景规则逐项判定（非适用场景标"不适用"）
□ 杯赛/欧战专项核查表：逐条判定，禁止只写其中几条
□ 情境因子：三态标注（触发/不触发原因/无数据原因）
```

### 推论层（示例：26 项）

```
□ 每项修正必须有数值 + 触发判定
□ 不触发必须写原因
□ 🔴 未列出 = 未执行 = 分析未完成
```

### 专项模块（联赛/杯赛/深盘）

```
□ 应触发模块是否实际调用（技能/脚本）
□ 逐条规则判定（触发/不触发 + 数值）
□ 禁止用通用查表代替专项模块调用
□ 实力差距等特殊规则有数值
```

### 方向判定

```
□ 各方向规则逐条判定
□ 平局信号逐条计数
□ 方向结论 + 置信度（含降级理由）
□ 并列/唯一规则是否正确执行
```

### 大小球深度

```
□ 大小球概率有数值
□ 总进球分布有各档概率
□ 外部期望（xG/λ）有数值或标注无数据
□ BTTS 判定
□ 大小球倾向 + 量级
□ 信号强度标签（强/中/弱/中性）明确
□ 偏差校准有数值（如有）
```

### 比分谱系

```
□ 数值主模型（λ + 每比分概率）
□ 主客因子对照（如有）
□ 净胜双出口核对（深盘 + 大球强 → 次锚覆盖）
□ 盈亏矩阵/去水比分概率
□ 比分推荐 3–4 个：主锚/次锚（命中计入）+ 第 3/4 候选（标注不计入）
□ 锁定规则：高概率区间/低概率区间
□ 停止分支：大球/小球出口
□ 候选池规模 + 尾部标注
```

### 总进球与自检

```
□ 概率化输出（大球/小球/中心值）
□ 凯利联动
□ 交叉验证一致/矛盾
□ 自检表逐项打勾 + 证据；条件层三态标注
□ 🔴 无证据 = 未执行 = 禁止通过
```

### 落盘

```
□ 存档结构完整
□ 事件 ID 记录
□ 结论表在最前
```

## 二、传导性审计（步骤间输入输出是否衔接）

| 传导链 | 检查内容 |
|:--|:--|
| 去水 → 硬核层 | 去水概率是否用于硬核项 |
| 大小球 → 水位联动 | 大小球数据是否输入水位分析 |
| 诱盘 → 场景 | 诱阻结论是否输入场景判定 |
| 场景 → 推论 | 场景结论是否输入推论 |
| 推论 ↔ 子模型 | 推论项是否与子模型规则交叉验证 |
| 子模型 ↔ 主客因子 | 联赛校准是否与主客场偏移对照 |
| 主客因子 → 方向 | 主客场 λ 是否输入方向判定 |
| 方向 → 大小球 | 方向结论与大小球信号是否一致/矛盾标注 |
| 大小球 → 比分 | 大小球量级是否决定比分候选池 |
| 比分 → 总进球 | 比分 Top 概率是否汇总为总进球概率 |
| 全链 → 自检 | 所有前置结论是否在自检中复核 |

**🔴 审计规则**：**发现传导断裂 = 不通过**。前一步的输出必须在后一步中被消费，不能"各说各话"。

## 三、模块与脚本活跃度审计

| 模块/脚本 | 应触发条件 | 检查 |
|:--|:--|:--|
| 主预计算脚本 | 每场必跑 | 输出是否包含必核清单 |
| 方向引擎 | 有欧赔时 | 方向结论是否引用其输出 |
| 进球分布模块 | 有总进球赔率时 | 大小球深度是否引用 |
| 查表模块 | 有大小球盘时 | 量级是否查表 |
| 主客场因子 | 有主客场数据时 | 是否调用 |
| 杯赛模块（多回合/小组赛） | 杯赛赛事 | 场景步骤是否调用 |
| 联赛子模型 | 已校准联赛 | 是否逐条判定 |
| 学习/复盘脚本 | 赛后 | 是否记录案例 |
| 数据接入（含网络参数） | 完整分析 | 是否加了网络参数 |
| 数据源健康检查 | 每场分析前 | 是否有健康表 |
| 伤停影响计算 | 有伤停信息时 | 是否算了影响分 |

**🔴 审计规则**：**应触发但未触发 = 不通过**。无数据时必须三态标注，**禁止静默跳过**。

## 四、数值证据审计

1. **每项判定必须有数值**：不允许"看起来""大概""应该"等模糊词
2. **去水概率必须计算**：不直接用赔率当概率
3. **赔率变动必须列数值**：不允许"降赔"两个字带过，必须写 **从 X.XX → Y.YY**
4. **比分概率必须排序**：不允许只给主锚不给概率分布
5. **三态标注必须显式**：有数据 = 数值 / 无数据 = 原因 / 不触发 = 条件

## 五、输出格式审计

| 必输出项 | 位置 |
|:--|:--|
| 结论表（方向/置信度/主锚次锚/总进球/半场/BTTS） | 最前面 |
| 方向结论 + 置信度 | 方向判定末尾 |
| 大小球信号标签 | 大小球步骤 |
| 比分主锚/次锚 + 第 3/4 候选 | 比分步骤 |
| 总进球概率 + 中心值 | 总进球步骤 |

| 风险提示 | 末尾 |

## 七、审计铁律

1. **禁止因为分析"看起来专业"就通过**——必须逐项核对
2. **未列出 = 未执行 = 不通过**——流程定义了 N 项，没写就是没做
3. **三态标注是强制的**——无数据必须写原因，不能假装数据存在
4. **传导断裂是严重问题**——前一步结论没被后一步消费 = 分析割裂
5. **数值证据是底线**——所有判定必须有数字支撑
6. **本审计提示词通用**——适用于任何版本，自动适配当前流程定义
7. **审计不修改分析**——只报告问题，不替分析者补内容

> 🔴 **与「② 完成度检验」的区别**：
> **② 检验** = 自查 + **补充**（发现问题就补，并更新结论）；
> **③ 审计** = 独立复核、**只报告不改**（保持审计的独立性）。
> 两者可配合使用：先用 ② 自查补全，再用 ③ 交叉验证。
