# SK-audit — 模型审计（融合 V3.0 + V4.0）

> 🔴**被动 skill**：仅在用户提出审计要求时读取执行；常规分析/复盘**不触发**。
> 🔴**审计不修改被审对象**（B 模式）· **审计发现问题必修到可验证**（A 模式）。

## 🔴 host 工具链纪律（锁规避）
bash 被报 `cannot declare which files it changes while a read-evidence requirement is outstanding` = 缺"写入边界声明"（非"读不够"）。
① **声明生成**: `python data/tmp/lock_dirs.py --scan`（自动扫描子目录·防漏）
② **顺序**: write/edit → 下一轮 read → bash + 全量声明（一次跑完）
③ **轮末编辑**: 多文件编辑放轮末；**兜底**: edit_file 不受锁影响
（详见 AGENTS「read-evidence 锁解法」节）

## A 模式：模型工程审计（V3.0·8 维）

### A1 动态探查（12 动作·建全量清单·不允许硬编码数量假设）
```
① 文件清单（.py/.md/.json/.toml/.csv 全量+时间戳）  ② 脚本清单（功能/被谁调用/调用了谁）
③ Skill 清单（触发/输入输出/调用脚本）             ④ 规则清单（编号/触发/逻辑/优先级/案例）
⑤ 数据文件清单（字段/样本量/更新时间/消费方）       ⑥ 配置文件清单
⑦ 上下文文档清单（版本/引用）                      ⑧ 一致性校验机制（check_sync 基线）
⑨ 案例库基线（数量/字段/口径）                     ⑩ 数据源与监控机制
⑪ 数据格式基线（竞彩 txt 实际格式 vs 提取函数期望·重点：逗号分隔/球后缀/节标题变体）
⑫ 参数完整性基线（模块签名 vs 调用处实传·缺参=功能降级）
```

### A2 八维审计（每维输出问题清单·P0-P3 分级）
```
① 完整性：脚本语法全过 / Skill 非空 / 规则有编号 / 数据字段完整 / check_sync 全绿
② 逻辑性：无规则冲突 / 无循环依赖 / 无遗漏分支 / 边界明确 / 优先级无越级 / 数学正确
③ 传导性（核心）：10 条链路逐条验（去水→方向 / 方向→净胜档 / 量级→候选池 / 伤停→调整 /
   平局聚合→方向 / 让球分层 8 因子 / 欧战 / 联赛子模型 / 融合→判定 / 锚-市场一致性）
   + 每个中间产物有上游来源与下游消费方 · 无孤儿产物 · 无断裂引用
④ 可靠性：确定性 / 异常降级 / 无硬编码 / 无魔法数字 / 异常不静默
⑤ 活跃性：无僵尸 Skill/脚本/规则/数据 / 存在≠活跃（必须实跑验证）
⑥ 上下文衔接：版本号统一 / 引用存在 / 描述与实现一致 / 更新已同步
⑦ 性能可维护：耗时 / 冗余计算 / 配置集中 / 命名 / 注释
⑧ 实际运行验证（🔴V3.0 核心·最高优先级）：
   用真实 txt 跑 calc_all 主流程 → 验证【模块易见性/参数传递/因子实际计算/输出被消费/数据格式匹配】
   + 边界场景（深盘/超深盘/欧战/平局各 ≥1 例）+ 同场跑 2 次确定性
```

### A3 修复与验证
- P0/P1 **必须本次修复到可验证状态**（禁"标注待办"）· 修复顺序：数据格式不匹配 → 参数缺失 → 输出未消费 → 存在≠活跃
- 修复后**全量回归**：`check_sync` 全绿 + 关键脚本复跑 + 涉及链路整链验证 + 副本同步

### A4 报告（模板）
```
审计概览（范围/问题数/修复状态）→ 全量清单摘要 → 问题清单（编号/等级/模块/根因/影响/修复/验证）
→ 传导链路验证表 → 实际运行验证表 → 修复记录 → 验收结论（各维 ✅/❌ + 总体通过/有条件/不通过）
```
📌 **A 模式详版逐项清单**见 `data/tmp/audit_prompt.md`（通用版提示词·版本/数字以实际读取为准）。

## 🔴 共用铁律（两模式）

1. **A 模式：「存在≠活跃」**——文件存在 ≠ 功能生效；必须实跑验证参数传递/因子计算/输出消费
2. **B 模式：「未列出=未执行」**——模型定义了 26 项修正/22 项自检，没写就是没做
3. **三态标注强制**——无数据必须写原因·不触发必须写条件·禁止"没做也不说"
4. **数值证据底线**——所有判定必须有数字支撑
5. **审计不修改分析**（B）· **审计必修到可验证**（A）
6. **禁用"看起来专业"通过**——逐项核对·宁严勿松
7. **报告即交付**——审计报告落盘 `docs/审计报告_<日期>_<模式>.md` + （A 模式）修复与回归证据
8. **术语差异≠缺陷**——审计项若引用**外部术语**（如别处规范里的「L1-L7 七档量级」），而模型用**等效自有体系**（txt 竞彩总进球 8档 + goal_bins 5档 + 三档信号强度）→ 判为「**术语差异·非 P 级问题**」；🔴**禁为满足审计而引入外部体系**——量级/口径**唯一基准 = txt 竞彩格式 + 欧亚盘数据**（决策: L1-L7 不引入）
9. **改动分层纪律（引用 SK-model-maintenance「数据链三层风险」）**——A 模式给修复建议时必须标注**所处层**：①输入/解析层（🔴高危）/ ②数据表层（🔴改键=静默失效）/ ③展示留痕层（🟢安全区）；**新增「标注/别名/档位显示」一律建议放第③层**（只读消费现有表·不改任何字段读法）
