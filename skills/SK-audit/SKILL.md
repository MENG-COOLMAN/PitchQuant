### A1 动态探查（**20 动作**·建全量清单·不允许硬编码数量假设）
```
① 文件清单（.py/.md/.json/.toml/.csv 全量+时间戳）  ② 脚本清单（功能/被谁调用/调用了谁）
③ Skill 清单（触发/输入输出/调用脚本）             ④ 规则清单（编号/触发/逻辑/优先级/案例）
⑤ 数据文件清单（字段/样本量/更新时间/消费方）       ⑥ 配置文件清单
⑦ 上下文文档清单（版本/引用）                      ⑧ 一致性校验机制（check_sync 基线）
⑨ 案例库基线（数量/字段/口径）                     ⑩ 数据源与监控机制
⑪ 数据格式基线（竞彩 txt 实际格式 vs 提取函数期望·重点：逗号分隔/球后缀/节标题变体）
⑫ 参数完整性基线（模块签名 vs 调用处实传·缺参=功能降级）
🔴⑬ 口径一致性探查（2026-09-28 新增·根治 P0-1「同一模块三处口径不一致」）
    对象: 所有查表类模块（nl_model BANDS / score_depth_table / league_table / water_table /
          goal_bins_table / deep_anchor_table / draw_table / quadrant_table）
    动作: 三处口径并排 —— ① 建表时用的输入字段  ② 运行时查表函数收到的变量  ③ 下游消费点的变量
    断言: 三者在**同一坐标空间**；发现跨函数偏移量不一致（如 −65 / +60.7）= **P0**
    🔴 脚本: `python data/tmp/audit_alignment.py`（nl_model 硬断言 + 7 表并排·exit≠0 即有 P0）
🔴⑭ 提取函数真实样例回归（2026-09-28 新增·根治 P0-2「正则在真实 txt 上全不命中」）
    把 3–5 份**真实竞彩 txt 原文**固化为 fixture（`data/tmp/_audit_fixtures/`·只增不改）：
    必覆盖 ① 五大联赛标准（`赛事：X 周YNNN A(主) VS B(客)`）② 欧国联/对阵行格式
    ③ **期号在前变体**（`赛事：周三006 西甲 …`）④ 无轮次格式
    对每个 parse/extract 函数（`extract_nl_teams` / `parse_matchday` / `txt_features` /
    `_parse_teams` …）跑一遍，**断言主客名/轮次/赔率字段非空且正确**
    任何 fixture 返回 None/空 = **P0**（这正是 calc_all 正则的漏网点）
    🔴 脚本: `python data/tmp/audit_fixtures.py`（exit≠0 即有 P0）·check_sync 自动跑
🔴⑮ 规则–代码双向核对（2026-09-28 新增·根治 P1-5「文档写了±10pp降档但代码没落地」）
    正向: 文档（SKILL.md / SK-league-*）里每条「R 规则 / 铁律 / 必须 X 才 Y」→ grep 代码有无
          对应分支或参数；**文档有代码无 = P1（规则悬空）**
    反向: 代码里硬编码常数（`matchday=1` / `ELO_OFFSET=65` / 写死概率阈值）→ 回文档找声明；
          **有声明但用错位置 = P0**（本次 P0-4）；**无声明 = P1（魔法数字）**
🔴⑯ 启用依据泄露探查（2026-09-30 新增·根治「用赛后统计做回测据以启用」·P-LEAK-1）
    ① 任何回测的**特征集**逐项分类: 赛前可得 / 赛后统计 / 未来信息
       → 含赛后统计者**直接判泄露**（案例: validate_fusion.py 26 特征含 17 个赛后统计 → +0.68pp 虚高）
    ② 对照实验: **只留赛前可得特征**重跑同一回测 → 看增益真实值
       （案例: 227,518 场 → 仅赛前可得 50.35% vs 基准 50.34% = **+0.01pp ≈ 0**）
    ③ 启用裁定须**三重证据**: 回测(n) + 同场基准对照 + 独立旁证（案例: 融合监测 n=48 融合21=基准21）
    ④ **回测脚本禁止写回生产状态**（`state/*.pkl` / `*.json`）——
       案例: validate_learning.py 的 `RM.save_models(m)` 污染生产 StandardScaler → 输出数值爆炸
🔴⑰ 作用域 / 闭包陷阱探查（2026-10-20 新增·实抓 `_n23_g = locals().get` 静默失效）
    ① `xxx = locals().get` 绑定的是**此刻的 dict 快照** → 之后定义的局部变量**永远取不到**（静默 None）
    ② **嵌套函数内的 `locals()` 只含自身参数** → 同样无法取外层局部变量
    ③ 判据: grep `locals()` / `globals()` 用于「动态取变量」→ 一律 P1（同作用域应直接按名引用）
    案例: `_n23_ht` 在 `_n23_g` 定义之后赋值 → 半场推断恒三态且**不报错**
🔴⑱ 配置字段消费探查（2026-10-20 新增·实抓 scope_registry `keys` 从未被读）
    凡 json/registry 里声明的字段 → grep 代码是否**真有读取点**；「字段写了、代码不读」= 存在≠活跃（配置空转）
    案例: `scope_for_league` 只查 name_contains/league_name_contains/league_id，漏读 `keys`
    → 五大联赛自上线起**作用域开关从未生效**（恒落「默认 ref 保守」）
🔴⑲ 输出一致性探查（2026-10-20 新增·实抓 N07 ❌ 与 N07b ✅ 自相矛盾）
    同一事实在**多处输出**时逐处比对：同一场的锚-市场校验若一处 ❌ 一处 ✅ → 读者必然误判
    判据: 收集全部 `❌/⚠️/⚪` 标记行 → 同一对象被两个校验器给出相反结论 = P1（须指回权威那条）
🔴⑳ 封装覆盖率探查（2026-10-20 新增·用户「避免每次手算带来误差」）
    列出「每次分析都要人工合成」的判定（置信度层/半场方向/并列排序/停止分支…）→
    标「已脚本化 / 建议封装 / 不宜封装(需当场判断)」；已脚本化者须在 calc_all 有**输出行**（否则=存在≠活跃）
    案例: 置信度层原纯手算 → 封 `confidence_engine.py`；半场方向原纯手判 → 接 `_bqc_to_ht_dist`
    ⑤ 🔴**状态落地完备性**（治「修一处漏三处」）: 某状态（如「L1 已否决」）写入时，
       必须遍历**其全部副本**: 运行时状态文件 / **代码默认值（重建路径）** / 迁移恢复文档 /
       校验器断言 / 规则登记表 / 本审计 skill ——「一致」≠「都改了」
       （案例: `gate.py default_gate()` 仍 active/True/0.10 → gate.json 一旦重建会**复活**已否决的 L1）
```

## 🔴 共用铁律（两模式）

1. **A 模式：「存在≠活跃」**——文件存在 ≠ 功能生效；必须实跑验证参数传递/因子计算/输出消费
   🔴(2026-09-28 升级) 判准 = **用真实输入跑一次，输出里出现非空数值**（文件在+调用在+输出空 = 不活跃）
2. **B 模式：「未列出=未执行」**——模型定义了 26 项修正/22 项自检，没写就是没做
3. **三态标注强制**——无数据必须写原因·不触发必须写条件·禁止"没做也不说"
4. **数值证据底线**——所有判定必须有数字支撑
5. **审计不修改分析**（B）· **审计必修到可验证**（A）
6. **禁用"看起来专业"通过**——逐项核对·宁严勿松
7. **报告即交付**——审计报告落盘 `docs/审计报告_<日期>_<模式>.md` + （A 模式）修复与回归证据
8. **术语差异≠缺陷（2026-09-19 固化）**——审计项若引用**外部术语**（如别处规范里的「L1-L7 七档量级」），而模型用**等效自有体系**（txt 竞彩总进球 8档 + goal_bins 5档 + 三档信号强度）→ 判为「**术语差异·非 P 级问题**」；🔴**禁为满足审计而引入外部体系**——量级/口径**唯一基准 = txt 竞彩格式 + 欧亚盘数据**（2026-09-19 决策: L1-L7 不引入）
9. **改动分层纪律（引用 <REDACTED_SK>「数据链三层风险」）**——A 模式给修复建议时必须标注**所处层**：①输入/解析层（🔴高危）/ ②数据表层（🔴改键=静默失效）/ ③展示留痕层（🟢安全区）；**新增「标注/别名/档位显示」一律建议放第③层**（只读消费现有表·不改任何字段读法）
