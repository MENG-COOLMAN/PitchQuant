## 触发后的标准动作

**单图**：
```bash
python data/tmp/image2txt.py "<图片>" --league "<联赛>"
```

**🔴 多图（竞彩「赔率变化」页的实际形态·2026-11-01 用户真实截图验证）**：
```bash
python data/tmp/image2txt.py 图1.png 图2.png 图3.png \
       --league 英超 --teams "维拉,富勒姆" --kickoff "2026-11-01 04:00"
```
竞彩的赔率变化页按玩法分屏：**胜平负/让球一屏、总进球/半全场一屏、比分一屏、赛事信息一屏**
→ 单图只能拿局部，**必须多图合并**才能凑齐 5 玩法 + 多时点。合并规则：同玩法取「时点最多的那一份」。

| 参数 | 何时必传 |
|:--|:--|
| `--league` | 始终建议（缺了赛事行写「未知联赛」→ 队名会被 txt_normalize 污染） |
| `--teams "主,客"` | **一般不用传** —— 赛事页会自动回退 glm-4.6v 提取队名（见上节）；仅在「没有赛事页」或提取错时才手传 |
| `--kickoff` | 需要时效判断（`match_state`）时传 |

一步完成：`glm-ocr 版面识别 → 结构化解析 → 标准竞彩 txt → txt_normalize 校验`

产物：
- `data/tmp/ocr_out/<stem>.ocr.md` — OCR 原始版面（留痕/复核用）
- `data/tmp/ocr_out/<stem>.std.txt` — **标准竞彩 txt**（喂 calc_all / pipeline）
- `data/tmp/std_<stem>.std.txt` — txt_normalize 规范化产物

## 🔴 单时点 vs 多时点（决定哪些层可用）

| 截图类型 | 判定 | 可用层 |
|:--|:--|:--|
| **赔率变化页**（每行「时间+赔率」） | 多时点 ✅ | Step1-9 全套 + **V1 双源变动 / D1 背离 / 竞彩逐T形态学 / 低赔大幅变动重排** |

脚本会在输出末尾直接打印 `✅ 多时点（N 个）` 或 `⚠️ 单时点`，照抄进 raw 即可。

## 🔴 为什么赛事页「识别不出来」（2026-11-01 实测根因·已修）

**根因：glm-ocr 是「文档 OCR」，不是通用视觉模型。两种能力边界完全不同——**

| | `glm-ocr`（layout_parsing） | `glm-4.6v`（视觉大模型） |
|:--|:--|:--|
| 定位 | 扫描件/PDF 版面文字提取 | 通用图像理解 |
| 赔率表（规整 HTML table） | ✅ **完美** 1693-1721 tokens | 可以但更贵 |
| 赛事页（深色横幅+队徽图+条形图） | ❌ **判成 image 区域** 仅 **36 tokens**（只出「特征分析」四个字） | ✅ 全读出 2288 tokens |
| 耗时 | 0.8-2.0s | 10.4s |
| 计费 | 走 OCR 资源包（不扣现金） | 扣现金余额 |

赛事页的 `prompt_tokens` 只有 **33**（正常 600+）= 它**几乎没处理图像内容**，把整页当成了 2 张 `image`。
这不是脚本 bug，是模型能力边界。

**修法：自动分流（`ocr_one`）**
1. 先跑 `glm-ocr`（便宜）
2. 判质量：**无 `<table>` 或 tokens < 200** → 认定信息量过低
3. 自动回退 `glm-4.6v`，并从它的「【结构化JSON】」里提取 `match/league/kickoff`
→ 结果是**无需 `--teams`/`--league`/`--kickoff`，队名/联赛/开赛时间全自动**

实测（4 张图·全自动）：
```
[1/4] 赛事页   glm-ocr 36 tokens → 回退 glm-4.6v → 🎯 维拉 VS 富勒姆 ｜ 🕐 2026-11-01 04:00
[2/4] 胜平负    glm-ocr 1693 tokens → 6 时点
[3/4] 总进球    glm-ocr 1721 tokens → 4 时点
[4/4] 比分      glm-ocr 1691 tokens → 46 条
→ 【赛事】英超 维拉(主) VS 富勒姆(客) ｜ 比赛时间：2026-11-01 04:00  ← 零手动参数
```

## 🔴 实测踩过的 6 个真坑（2026-11-01·真实竞彩截图·已全修）

| # | 坑 | 现象 | 修法 |
|:-:|:--|:--|:--|
| 1 | **玩法名在 Markdown 标题里**，不在表格 cell | 全部 0/5 空 | `build_sections()` 按 `## xxx` 切分 |
| 2 | **标题匹配顺序**：「让球**胜平负**」「半全场**胜平负**」都含「胜平负」 | 胜平负 12 条、让球 0 条 | **长词优先**：`('让球','半全场','总进球','比分','胜平负')` |
| 3 | **表头行的数字被当赔率**（总进球表头 0/1/2/3/4/5/6） | 总进球 5 条（应 4） | 含「发布时间」的行跳过 |
| 4 | **让球值恰在表头行**（`让球-1彩果:`） | 跳过表头后让球变 +0 | 让球提取**放在表头跳过之前** |
| 5 | **比分表头就是标签行**（`发布时间|1:0|…|胜其它`） | 比分丢 13 个主胜标签 | 表头行在比分模式下**仍收集标签** |
| 6 | **赔率带涨跌箭头**（`1.82↓`/`3.50↑`） | 数值全匹配不到 | `ARROW` 正则先剥离 |

## 🔴 后两个真坑（2026-11-01 第二轮实测·巴列卡诺 vs 塞尔塔）

| # | 坑 | 现象 | 修法 |
|:-:|:--|:--|:--|
| 7 | **特征分析带斜杠** | OCR 出「2胜/5平/3负」，而 `calc_match.parse_features` 正则是「2胜5平3负」**不含斜杠** → 解析返回空 → 修正53 S4/S6 全失效 | `_clean_form()` 去斜杠 |

## 🔴 全流程实测暴露的真断链（2026-11-01·科莫 vs 威尼斯）

**现象**：`calc_all` 打印 `R-ANCHOR-BIG: 本场 E=3.56 → 次锚须 ≥ 5 球`，
但最终次锚仍是 **3:1（4 球）** —— **只报警不动作**。

**根因**：`big_pool_policy.anchor_requirement` 算出要求后**只 print**，
`joint_solver.joint_anchor` 从不接收 → 与 AGENTS P18「存在≠活跃」同型。

**修法**：
1. `joint_anchor(..., second_min_goals=None)` 新签名
2. return 前在**池内**找「总进球 ≥ N 且 ≠ 主锚」的最高分候选替换次锚（找不到 → 三态保留）
3. `calc_all` 用 `_bp_need_second` 透传

**实测**：科莫场 `3:1(4球) → 3:2(5球)` ✅ ；维拉/巴列卡诺（非大球场）`L0 次锚不受限` 未误伤 ✅

🔴 **踩坑**：锚是**字符串** `"3:1"` 不是元组 → `a2[0]+a2[1]` = `'3'+':'` TypeError
→ 必须用 `_totv()` 解析（`split(':')`）。

## 🔴 机制缺陷：分级只约束次锚，主锚裸奔（2026-11-01 用户质疑实证）

**用户质疑**：「3:2？你确定吗，让球盘让一球？而且都说了极端大球，你还主锚 2:1？是机制的问题吗」

**核实成立，是机制问题（三处）**：

| # | 缺陷 | 实证 |
|:-:|:--|:--|
| 1 | **P52 分级只约束次锚** | `big_pool_policy` 要求表只有 `'L4': (..., '次锚须 ≥ ⌈E+0.5⌉')`，**主锚没有任何分级要求**；输出里那句「主锚须≥3球」是 `joint_solver` 里**硬编码的 notes 文字**，不是真约束 |
| 2 | **P17 穿盘只是扣分不是硬约束** | `_signal_support` 的让球分项 `max(0, 1 - _gap*0.5)` → 净胜不足只扣分（P28「不淘汰任何候选」），矩阵+波胆分高就能压过去 |
| 3 | **结果两个锚都输盘** | 让 -1.5 的场次锚出 2:1（净胜1）与 3:2（净胜1）→ **在 -1.5 盘上都是输盘比分** |

**已修**：
1. `big_pool_policy.FIRST_MIN`（L5=4 / L4=3 / L3=3 / L2=2）+ `first_requirement()`
2. `joint_anchor(first_min_goals=..., second_min_goals=...)` + `_win_plate()` / `_legal()`
3. 终态合法性校验：**池内找不到合法次锚 → 置空，禁给输盘锚**

**实测（科莫 vs 威尼斯·让 −1.5·L4）**：
```
修前: 主锚 2:1（净胜1·输盘）/ 次锚 3:2（净胜1·输盘）
修后: 主锚 3:1（净胜2·赢盘·4球）/ 次锚 2:0（净胜2·赢盘·2球·未达≥5球下限已标三态）
回归: 平手盘/主让1球 均不触发（无误伤）
```

**🔴 用户追问「为什么让1.5不能是 4:1/4:0·你就这么死板吗」→ 又挖出更深一层**：

`_win_plate` 逻辑本身不排斥净胜 3/4，**但池里根本没有那些比分** —— 根因在：

```python
# calc_v3572.margin_candidates
if handi <= -1.2: return MARGIN_CAND['H2']    # 让1.5 → 硬编码净胜[1,2]
```

**让球档被硬映射成净胜档**，大球场次（λ≥3.4）本该有 4:0/4:1/5:1（净胜 3-4）却全被排除。
P43 只放宽了**校验层**（`market_net_band` ±1.5），**池生成层从未放宽** = 只校验不生成。

**修**：`_est_margin` 按 λ 追加净胜档（**只追加·main 不动**）：
| λ | 追加 |
|:--|:--|
| ≥4.0 | max+1, +2, +3 |
| ≥3.4 | max+1, +2 |
| ≥3.0 | max+1 |
| <3.0 | 不追加 |

**实测（科莫场·λ3.58）**：
```
修前: M(净胜)={1:55.5, 2:44.5}  池 5 个  次锚 2:0（凑不出≥5球）
修后: M(净胜)={1:35.1, 2:32.6, 3:20.6, 4:11.8}  池 10 个
     主锚 3:1（净胜2·赢盘·4球）/ 次锚 4:1（净胜3·赢盘·5球）  ✅ 两条都满足
```
回归：巴列卡诺 λ≈2.3 → M 仍 [1,2] 不扩 ✅

**⚠️ 仍未解决（诚实）**：`M 域（净胜档）只有 [1,2]`（亚盘 −1.5 只给 2 档）
→ 池仅 5 个候选，凑不出「赢盘 + ≥5 球」→ **次锚下限做不到，已三态标注而非静默失败**。
彻底修需放宽 M 域（L4 → 净胜档扩到 [2,3,4]），待后续。

## 🔴 消融审计器（2026-11-01·用户追问「为什么总遗漏」后的结构性回答）

**问题**：`check_sync` 1028 条断言基本是 `"x" in open(f).read()` = **源码级**，
「绿了」只证明代码在，不证明**生效**。所以伤停 12.9 分算出却不动作，一路绿灯。

**解法**：`audit_sensitivity.py` 扩展为 **6 变体消融**（每个信号关掉/改掉，看输出是否变）：

| 变体 | 消融内容 |
|:--|:--|

## 已知限制（诚实边界）

| 项 | 说明 |
|:--|:--|
| 联赛名 | 截图常无联赛 → 必须 `--league` 传，否则赛事行写「未知联赛」（不传会导致队名被 txt_normalize 污染成「【赛事】主队」→ HAF/N27 全失配） |
| 比赛时间 | 截图无开赛时间 → txt 里写「（截图缺·三态）」；影响 `match_state` 与时效判断 |
| 队名口径 | OCR 出的中文队名未必匹配 HAF/N27/Bzzoiro 表 → 分析时按三态处理，不硬套 |
| 多图合并 | ✅ **已实现**（一条命令传多张图，同玩法取时点最多的那份） |
| 赛事信息页 | ✅ 已自动回退 glm-4.6v，**队名/联赛/场次编号/开赛时间/特征分析 6 行全部自动写入 txt** |
| 赛季措辞 | OCR 原样输出 `Regular Season 第9轮`，基准 txt 常见 `2026/2027赛季英超第9轮` —— 语义相同，不影响解析 |
| 比分档位 | glm-ocr 实测**丢尾部 8 档**（客胜 2:3/0:4/…/负其它 未识别）→ 比分偏少；可对同一张图重跑或人工补 |
| 比分盘 | 竞彩 CS 为截断分布，去水期望系统性偏高 → 只作谱系排序（既有结论，不变） |
