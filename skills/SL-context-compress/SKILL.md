# SL-context-compress — 批末压缩模块（V3.5.52+运行保障·2026-08-19批末化）

> 由主技能 SK-model-v3-analysis 在 **Step11** 触发——**不是每场自动压缩**，
> 而是用户发出汇总信号（"请你汇总这n场比赛的比分进球数和方向，并标明置信度"）时**批量压缩本批已完成场次**。
> 目的：每场分析完只落盘不压缩、积累本批，信号触发时一次批量压缩"本批分析过程细节"，
> 减少压缩调用次数；压缩不丢任何结论（raw 已落盘·六重持久化闭环）。

---

## 🔴核心铁律（先读）

```
1. 压缩时机唯一合法点 = 用户发出汇总信号（"请你汇总这n场比赛的比分进球数和方向，并标明置信度"）之后 + 本批所有场次 raw落盘【完成且校验通过】。
   raw 落盘 = 数据已持久化（源A竞彩+源B欧盘+API+结论），压缩对话细节才安全。
2. 禁止压缩未落盘场次 —— 本批任一场 Step10 未落盘前，任何压缩指令一律拒绝执行，先补齐落盘。
3. 禁止压缩导致丢失: 每场最终结论 / 案例库raw引用路径 / 待赛果状态 / R假设进度。
4. 压缩不是跳过分析 —— 每场分析必须完整走完 Step0-10，压缩只发生在信号触发+全批落盘之后。
5. 压缩后恢复保障: 记忆 + AGENTS.md + 技能 + raw/ 四重闭环，任何时刻可恢复完整工作状态。
6. 🔴水位安全阀: 若上下文用量已接近上限（>70%），允许【不等信号·提前压缩上一批已完成场次】，但绝不允许压缩未落盘场次。
```

## 🔴五不影响保证（硬性约束·用户指令 2026-08-17）

```
本模块为「纯规则文档·被动执行」——不引入任何算法改动、不消耗额外计算资源。
以下五条为硬性保证，违反任一条 = 模块违规，立即停止压缩并报告：

① 不影响模型本身性能:
   压缩不触碰硬核层12项/变动层5项/推论层26项的任何数值、阈值与规则
   分析准确率完全由 Step0-10 逻辑决定；压缩只整理对话可见性，模型规则零改动
   性能恢复: 压缩后从 记忆+AGENTS.md+技能+raw 四重闭环可恢复与压缩前完全相同的分析能力

② 不影响分析过程:
   压缩时机 = 用户汇总信号之后 + 本批所有场次 raw落盘【校验通过】之后（Step0-10 全流程零干扰）
   未落盘场次任何数据一律不压缩；压缩对象仅限【本批已完成且已落盘】的场次细节
   🔴水位安全阀（>70%）时允许提前压缩上一批已完成场次——仅限已完成且已落盘的场次

③ 不影响备份文件:
   压缩模块不读、不写、不删 data/backups/ 下任何文件（含快照与基线）
   备份文件只由「备份铁则」与显式命令管理；压缩与磁盘文件体系完全隔离
   （压缩对象 = 对话上下文，与 data/ 全部文件无交集）

④ 不影响记忆:
   压缩不调用 remember/forget；记忆只在「模型规则变更」时由显式工具更新
   压缩不改变 football-model-version 等任何记忆的正文、revision、索引

⑤ 不影响结果:
   压缩保留: 最终结论(方向/锚定比分/置信度/触发信号) + raw路径 + 待赛果状态 + R假设进度 + 自检表结论
   🔴压缩后结论一致性核对（必执行）: 对话保留摘要 vs raw/case{id} 落盘结论
     方向/锚定比分/置信度/待赛果 逐项一致 → 压缩完成（结果零变化）
     任一项不一致 → 从 raw 恢复该场摘要，本次不压缩，报告差异
   复盘/批量回测数据源 = raw/ 与案例库（非对话）→ 结果链完全不受压缩影响
```

## 防超限双保险（保证不达上限）

```
保险1 · 场前水位检查（每场 Step0 前执行）:
  评估当前上下文用量（长会话中主观判断 + 感知到最近工具输出巨大/重复）:
    用量 >70% → 🔴安全阀触发: 不等用户信号，先压缩上一批已完成场次（仅限已落盘），再开始本场 Step0
    用量 40-70% → 正常开始，积累本批·待用户汇总信号时批末压缩
    用量 <40% → 正常开始，积累本批·待用户汇总信号时批末压缩
  判断依据: 最近是否已连续分析多场、本场数据文件是否巨大（欧盘CS全量120比分等）

保险2 · 批末信号压缩（用户信号触发·非每场）:
  用户发出汇总信号（"请你汇总这n场比赛的比分进球数和方向，并标明置信度"）时:
  先确认本批所有场次 raw 已落盘（未落盘先补齐）→ 批量压缩本批分析过程细节
  → 上下文占用压回"每场结论摘要 + raw引用"级别 → 永远为下一批留出完整分析空间
```

## 执行流程（Step11·批末信号触发·逐项执行不可跳）

```
Step11-1 识别信号: 用户消息含"请你汇总这n场比赛的比分进球数和方向，并标明置信度"
         → 确认本批场次清单（case{id} 列表）
Step11-2 确认落盘: 逐一检查本批 raw/case{id}_{主队}vs{客队}.md 已写入且含五部分
         （①竞彩全文 ②Odds-API欧盘全文 ③API数据 ④基本面 ⑤模型结论）
         任一场未落盘 → 停止压缩，先补齐该场 Step10
Step11-3 定位压缩锚点: 取【本批第一场分析开始时的用户消息】唯一摘录
         （如"分析 XX vs YY"或该场竞彩txt首行，需在当前对话中唯一匹配）
Step11-4 执行压缩: 调用 compress 工具
         anchor = 本批第一场开始时的用户消息摘录（Step11-3）
         direction = after  （压缩从锚点到最后一个已完成轮次·保留活跃轮次=用户信号消息）
         focus = 必须保留:
           ① 本批每场最终结论（方向/锚定比分/置信度/触发信号）
           ② 每场案例库 raw 路径引用（case{id}）
           ③ 待赛果状态（盲测场）
           ④ R假设进度（R1-R5 的 x/3）
           ⑤ 当前生效的版本号与自检表结论
Step11-5 压缩后自检（逐项核对）:
         □ 本批每场 raw 落盘路径可查（结论丢失可从 raw 恢复）
         □ 本批每场最终结论完整保留
         □ 待赛果场次状态保留（后续时机B复盘可用）
         □ 记忆+AGENTS.md+技能仍可恢复完整工作状态
Step11-6 记录压缩点: 在输出中标注「🔒已批末压缩至 case{首}~case{末} 分析起点」
         （供下一批 Step11-3 定位新锚点时衔接）
```

## 压缩内容边界

| 压缩（释放） | 保留（不压缩） |
|:--|:--|
| 已完成场次的 V1-V5 逐T赔率变动明细 | 该场最终结论（方向/比分/置信度） |
| 硬核层12项逐项计算过程 | 案例库 raw 路径引用 |
| 欧盘 CS 全量120比分去抽水中间表 | 待赛果场次状态 |
| 新闻抓取全文/API返回原文 | R假设进度（x/3） |
| 精算交叉6步中间推导 | 自检表逐项核对结论 |
| 已完成场次之间的冗余对话 | 当前场次任何数据 |

> 原理：被压缩内容 100% 已持久化在 raw/case{id} 中，压缩只是移除对话副本，
> 需要回测时从 raw 读取，不产生任何信息损失（六重持久化闭环）。
