## 🔴host 工具链「read-evidence 锁」解法（2026-09-19 实测固化）

**现象**: bash 报 `bash cannot declare which files it changes while a read-evidence requirement is outstanding (<paths>)`。
**根因**(实测推翻"读不够"的理解): 缺的不是 read·而是 **bash 未声明"写入边界"**——某文件被 write/edit 后 host 要求下一轮 read 建立证据·此时 bash 若不声明会写哪些目录 → 被拒。
**解法**(实测对照组): bash 必须传 `additional_write_dirs` 列出**所有可能被写的目录**:
    additional_write_dirs = ["<workspace>/data/tmp", "<workspace>/data",
                             "C:/Users/12242/Desktop/足球预测模型", "C:/Users/12242/Desktop"]
对照结果: 不声明→拦 ｜ 声明→一次通过 ｜ read_file 全文重读但**不声明**→仍拦(故 read 不是解药)。
**配套纪律(3条)**: ① write/edit 后**下一轮** read_file(同批次内的 read 不算·host 明示) ② bash **永远带** additional_write_dirs(宁多勿漏·漏一个即拦) ③ **edit_file 不受此锁影响**(可作兜底写入通道)。
**顺序模板**: ①edit/write → ②read(下一轮) → ③bash+声明(一次跑完 编译/测试/同步/校验)。
**❌反模式**: edit → bash(不声明) → 拦 → read → bash(不声明) → 仍拦 → 误判"状态不可清除"而陷入循环。
**已卡死解锁顺序**: ①带声明的 bash(通常立即解锁) → ②edit_file 兜底 → ③新会话。
