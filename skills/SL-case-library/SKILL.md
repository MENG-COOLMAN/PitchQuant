# SL-case-library 案例库自动维护技能

> 用途：让每次预测都有据可查，回测复盘有依据。
> 位置：data/case-library/（README/实战案例.md/.csv + 回测规律.md/.csv）
> 🔴**统一模板（案例库唯一权威格式）**: `data/case-library/案例库模板.md`
> - CSV 固定 15 列（预测比分合并单列·禁止拆多列）·raw 固定七节（一竞彩/二欧盘/三场景/四基本面/五结论/六硬核层12项/七xG）
> - case103 起强制按模板·历史 case01-102 数据缺失不管·不回溯不重构
> - 本技能以下规范与模板冲突时·以模板文件为准

## 两个触发时机

```
时机A（预测前·分析完成出结论时）: 写入"预测记录"，标记状态=待赛果
时机B（预测后·赛果已知时）:       补写"赛果+命中+复盘"，更新R假设进度
```

**触发入口**：
```
时机A: 主技能 SK-model-v3-analysis 在"最终输出"后自动调用（无需用户额外指令）
时机B: 用户带回赛果时（如"XX队 2-1 赢了"/"赛果2-1"），
       识别为复盘请求 → 定位待赛果的case → 执行时机B
       触发词: 赛果/比分/结果/赢了/输了/复盘 等
```

## 时机A：预测前记录（分析结论产出时执行）

### 两类数据源（都必须写入案例库）

**数据源1 · 用户提供（原始输入）**：
```
队伍名称: 主队 / 客队（用户给的名称，保留原样）
竞彩赔率: 胜平负 / 让球 / 总进球 / 半全场 / 比分 的完整变动序列
          （初盘→临场 每一T的数值+变动%）
```

**数据源2 · API计算（推导数据）**：
```
欧亚盘:   14家机构 胜平负/让球/大小球 赔率
抽水率:   竞彩 vs 欧盘 各算一遍
水位:     全盘水位 + 方向偏移 + 水位赔率联动
凯利:     凯利指数
基本面:   H2H / 近10场 / ELO / 伤停阵容
🔴Odds-API 欧盘双源（源B·欧战/有MCP时必存）:
  当前赔率:  get_odds 全文（1X2/让球Spread/大小球Totals/半全场HT-FT/比分/BTTS，1xbet+Bet365）
  变动线:    get_odds_movements 全文（ML + Spread亚盘水位，带时间戳）⚠️免费tier 404时存 get_odds Spread/Totals 盘口+水位替代
```

## 时机B：预测后记录（赛果已知时执行）

### 补写字段（含用户赛后输入的真实比分）

| 字段 | 说明 | 来源 |
|:--|:--|:--|
| 真实比分 | 实际赛果（如"2-1"） | 🔴用户赛后告诉 |
| 方向命中 | 是/否 | 计算 |
| 比分命中 | 是/否（锚定比分是否含真实比分） | 计算 |
| 完美命中 | 方向✅且比分✅=是 | 计算 |
| 复盘结论 | 只复盘方法论，禁止反推新规则 | 我 |

> 🔴 真实比分是**数据源3（用户赛后输入）**，必须原样填入 md + csv 双份。
> 用户可能说"XX队2-1赢了"或"赛果2-1"，都要提取出标准比分填入。

### 命中判定规则
```
方向命中: 预测方向 == 真实赛果方向
🔴比分命中(case50起·2026-08-20用户指令): 真实比分 == 主锚(预测候选池第1位) 或 == 次锚(第2位)
  → 其余候选(第3/4位·停止分支·高比分出口等)命中不算比分命中·仅方向命中仍计
  → 🔴历史case01-49保持旧口径(候选池任意命中即算)·case49已按旧口径录入(1:0第4候选命中算✅)
完美命中: 方向命中 && 比分命中
```

### R假设进度追踪（核心）

**统一标准：完美命中（方向✅ 且 比分✅）才 +1。**
原因：完美命中最严格、无歧义，杜绝"事后归因"污染（R2/R3 尤其如此）。

```
R1 平赔锁死→平局锚定:     完美命中+1（预测平局，方向比分都对）
R2 基本面碾压→大幅出口:   完美命中+1（锚定需含大幅比分 3-0/4-0）
R3 伤停叠加→平局:         完美命中+1（预测平局）
R4 LOW层信号冲突→方向可信: 完美命中+1（验证LOW层方向）
R5 让平防御→主胜1球:      完美命中+1（锚定需含主胜1球类 2-1/1-0）
```
> 五个R假设统一用「完美命中」计数，禁止混用"方向命中"/"比分命中"导致标准不一。

### 批量更新检查（🔴20-30场周期·防单场过拟合）

```
每场（时机B）:
  只记录赛果+命中+R假设进度计数
  复盘结论标记"观察"，不立即固化规则

批量更新（累积20-30场触发）:
  IF 总场次>=30 或 欧战场次>=20:
     → 🔴提醒用户"该批量更新模型了"
     → 全面回测: 统计方向/比分/大球命中率
     → 固化规律: 达标的R假设(≥3场同向) + 新发现规律
     → 更新 memory football-model-version 版本号

为什么: 单场=1样本噪声主导；20-30场才统计显著
```

### 执行步骤
```
1. 🔴**调 `python data/tmp/case_write.py review --file <参数.json>`**（自动判定方向/比分/完美命中·自动追加 raw 复盘节·写后读回校验）——禁止手写 CSV
2. 更新 R假设进度（仅计数，不立即固化）
4. 🔴场次统计: 运行 python data/count_cases.py 统计总场次+欧战场次
5. 🔴批量更新提醒: 总场次>=30 或 欧战场次>=20 → 提醒用户批量更新
6. 报告: 案例已闭环 + 当前累积 X场(总)/Y场(欧战) + 距下一更新还差Z场
```

```

  data/case-library/实战案例.md   ← Markdown
```

## 复盘铁律（防过拟合）

```
1. 未命中 → 只复盘"方法论哪里漏了"，不新增规则
2. 事后归因的教训 → 标注"观察"，绝不直接变规则
3. 新规则必须 3场同向命中 才能固化
4. 严禁用赛果反推"假如有XX规则就好了"
```
