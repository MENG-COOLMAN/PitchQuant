## 一、CSV 模板（`data/case-library/实战案例.csv`·15 列固定）

```csv
case_id,日期,联赛,主队,客队,预测方向,预测比分,真实比分,方向命中,比分命中,完美命中,置信度层,触发信号,关联假设,复盘结论
103,2026-08-30,英超,主队A,客队B,主胜,2:1,1:1,待赛果,,,,HIGH,D1+G1,,
```

### 列定义（每列必填·无数据标「待赛果」或「」·禁止错位）

| # | 列名 | 填写规范 | 示例 |
|:--|:--|:--|:--|
| 1 | case_id | 自增整数（=现有最大+1） | 103 |
| 2 | 日期 | 比赛日 YYYY-MM-DD | 2026-08-30 |
| 3 | 联赛 | 联赛/赛事名（中文） | 英超 |
| 4 | 主队 | 主队名（用户提供原样） | 主队A |
| 5 | 客队 | 客队名（用户提供原样） | 客队B |
| 6 | 预测方向 | 主胜/平局/客胜·并列用「+」如「客胜+平局」 | 主胜 |
| 7 | 预测比分 | **单列**：主锚,次锚(,第3/第4 候选)逗号分隔·🔴禁止拆多列 | 2:1,1:1 |
| 8 | 真实比分 | 待赛果 → 赛后填「主:客」 | 待赛果 |
| 9 | 方向命中 | 是/否（预测方向含真实结果·含并列） | 是 |
| 10 | 比分命中 | 是/否（真实==主锚或次锚·case50+新口径） | 是 |
| 11 | 完美命中 | 是/否（方向✅且比分✅） | 是 |
| 12 | 置信度层 | HIGH/MID/MID-LOW/LOW | HIGH |
| 13 | 触发信号 | 信号编号+（如 D1+G1+H1+H2+铁则32） | D1+G1 |
| 14 | 关联假设 | R1-R5 或 无 | 无 |
| 15 | 复盘结论 | 赛后复盘要点（方法论·禁反推新规则） | 完美命中 |

### 🔴 CSV 铁律
1. **固定 15 列**·预测比分必须合并单列（逗号分隔）·禁止按候选数拆列（历史旧格式多候选列已废弃）
2. 每行必须 15 个字段·不足用空串补齐·禁止少列/多列
3. 方向命中/比分命中/完美命中 只允许「是/否/待赛果」
4. 新行追加在文件末尾·禁止修改历史行（历史缺失不管）

## 三、填写流程（预测前+赛后）

```
预测前（时机A·分析完成时）:
  ① raw 七节完整落盘（check_luopan 校验✅）
  ② CSV 追加一行（15 列·预测比分合并单列·状态=待赛果）
  ③ 实战案例.md 追加案例块（摘要+结论）

赛后（时机B·用户提供真实赛果时）:
  ① CSV 该行补真实比分/方向命中/比分命中/完美命中/复盘结论（判定规则见下）
  ② raw 追加「复盘」节（第八节）
  ③ check_luopan 复校验✅
  ④ 统计累计命中率·R假设进度（完美命中才+1）·批量更新提醒(20-30场)
```

## 四、命中判定口径（唯一）

| 项 | 口径 |
|:--|:--|
| 方向命中 | 预测方向含真实结果（含并列/次方向）即✅ |
| 比分命中 | **真实比分 == 主锚或次锚**（候选池前 2 位）·第3/4 候选命中不算（case50+新口径·case01-49 旧口径不回溯） |
| 完美命中 | 方向✅ 且 比分✅ |
| R假设进度 | 统一用「完美命中」计数·+1/场 |

## 六、🔴 填写规范铁律（防乱码/串码/遗失·2026-08-30）

> 案例库写入**必须走 `data/tmp/case_write.py` 脚本**（结构化·自动校验）·**禁止手写 CSV/手敲 raw**。

### 填写工具（唯一入口）
```bash
# 预测前写入（自动 case_id 自增·15 列·状态=待赛果）
python data/tmp/case_write.py add --file <参数.json>
# 赛果复盘（自动判定方向/比分/完美命中·自动追加 raw 复盘节）
python data/tmp/case_write.py review --file <参数.json>
```
参数 JSON 示例（键名=表头·必须一致）:
```json
{"日期":"2026-08-30","联赛":"英超","主队":"曼城","客队":"伯恩茅斯",
 "预测方向":"主胜","预测比分":"2:1,3:1","置信度层":"HIGH","触发信号":"D1+G1","关联假设":"无"}
```

### 三防线（脚本内置强制）
| 防线 | 机制 |
|:--|:--|
| **防串码** | 字段清洗：禁换行·信号禁逗号(用+连接·如 D1+G1)·预测比分格式校验(主:客,主:客)·键名=表头 |
| **防乱码** | 统一编码 utf-8-sig 读写·写后读回验证(15列·case_id 非空)·参数经 JSON 文件(UTF-8·避免命令行中文编码问题) |
| **防遗失** | 写后读回比对·raw 复盘节自动追加·字段不足补空(禁缺列) |

### 填写字段规范（每字段格式）
| 字段 | 规范 | 禁 |
|:--|:--|:--|
| 预测比分 | 主:客,主:客（逗号分隔·csv.writer 自动加引号） | 禁连字符 2-1（统一冒号）·禁空 |
| 触发信号 | D1+G1+H1（+连接） | 禁逗号·禁中文逗号·禁空格 |
| 方向命中/比分命中/完美命中 | 是/否（review 自动算） | 禁其他值 |
| 置信度层 | HIGH/MID/MID-LOW/LOW | 禁自定义层 |
| 复盘结论 | 一句话方法论（中文） | 禁空·禁反推新规则 |

### 🔴 铁律
1. 案例库任何写入**必须走 case_write.py**（add/review）·禁止手动编辑 CSV 或 raw
2. 参数必须 JSON 文件（UTF-8·键名=表头中文）·禁止命令行直接传中文参数（Windows 引号问题已验证）
3. 每次写入后脚本自动验证（读回 15 列·无乱码）·验证失败即报错·禁止带错落盘
4. 历史 case01-102 已统一·不手动改动
