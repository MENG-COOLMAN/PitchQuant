# 架构说明（Architecture）

> 本文件是运行总纲的公开精简版。完整运行规约由 LLM 运行时按 AGENTS.md 加载。

## 一、三层架构

```
第一层：硬核层（12 项）       —— 赔率结构：去水/隐含概率/盘口/凯利/分歧度
第二层：变动层（5 项 V1-V6）   —— 赔率动态：双源变动/诱阻识别/水位联动/盘口联动
第三层：推论层（26 项修正）    —— 规则推论：场景/联赛/主客场/战术/战意
```

**上游 → 下游传导原则**：每一步的输出 = 下一步的输入；传导链断裂即分析失败。

## 二、主流程（Step0 → Step11）

| 阶段 | 内容 | 关键动作 |
|:--|:--|:--|
| **PreStep** | 先验筛选（被动·用户指令触发） | 10 信号打分 → 筛选当晚可分析场次 |
| **Step0** | 数据获取 | 竞彩 txt / 欧盘 API / 新闻伤停 / H2H / ELO / xG / 官方概率（多源·三态标注） |
| **Step1** | 硬核层 12 项 | 去抽水 → 校准 → 方向差距 → skew → 凯利（统一欧盘口径） |
| **Step2** | 变动层 V1-V6 | 双源变动形态 / 诱阻四步 / 水位联动 / 半全场 / 跨市场分歧 / 盘口联动 |
| **Step3** | 场景规则 | 44/45/46 + 欧战基准集（rule51-70） |
| **Step3.5** | 情境因子 F1-F7 | 仅降级/标注，禁止假精度系数 |
| **Step4** | 推论层 26 项修正 | 逐项触发判定（不触发须写原因） |
| **Step4.5** | 联赛子模型 | 五大联赛各独立 skill（R1-R20 规则集） |
| **Step4.6** | 主客场因子（HAF） | 对抗耦合 λ + 主客场偏移（只用对应场地子集） |
| **Step5** | 方向判定 | D1-D4 + 平局信号聚合 + R20 平局温度 + 弱共识铁律 |
| **Step6** | 大小球深度 | O2.5/O3.5 → 总进球档分布 + 信号强度三档 |
| **Step7** | 比分谱系 | 泊松主引擎 + 查表融合 + 净胜档候选池 + 锚-市场一致性 |
| **Step8** | 总进球 + 交叉验证 | 概率化输出 + 凯利联动 |
| **Step9** | 强制自检 | 22+ 项逐项打勾（每项附数值证据） |
| **Step10** | 落盘 | raw 八节存档（含执行留痕）+ 案例库写入 |
| **Step11** | 批末压缩 + 投注方案 | 用户信号触发（被动） |

## 三、规则优先级体系（冲突裁决）

```
L1 铁律（不可覆盖）     : 双源原则 / 动态数据铁律 / 比分命中口径 / 禁单场固化
L2 硬核层（n≥1000 回测）: 硬核 12 项 / R1-R20 / 欧战 rule51-70
L2.5 范围内优先         : 联赛子模型 / 欧战规则（仅对应场景生效）
L3 变动层（仅调置信度）  : V1-V6 / 平局信号 / HAF / xG（验证信号·不反转方向）
L4 推论层（仅参考标注）  : 推论 26 项 / 情境因子 / 战术疲劳观察项
L5 观察项（仅记录）      : 已否决或待验证项
```

**冲突解决**：低优先级不得覆盖高优先级；同级冲突以"更近期回测 + 更大样本"为准。

## 四、质量保障机制（四道门）

| 门 | 脚本 | 作用 |
|:--|:--|:--|
| 预计算门 | `calc_all.py` | 一次性跑完所有确定性计算 + 生成必核清单（防 LLM 自我遗漏） |
| 输出门 | `output_checker.py` | 35 个必填块机械校验（缺失即拦截） |
| 落盘门 | `check_luopan.py` | raw 存档结构校验（八节 + 六子块留痕） |
| 一致性门 | `check_sync.py` | 238 条规则/文档/数据同步校验（改了什么就校验什么） |

## 五、数据链三层风险（改动纪律）

```
① 输入/解析层（txt 解析 / API 抓取）  🔴 高危 —— 字段错位/静默失效
② 数据表层（查表 JSON）               🔴 高危 —— 改键名=下游静默失效
③ 展示/留痕层（输出行 / 模板 / 校验器）🟢 安全 —— 新增标注只允许放这层
```

**自检问句**：「这条改动会不会改变任何已有字段的读法？」→ 会 → 停手重设计。
